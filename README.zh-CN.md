# YuCe（玉策）

**面向 AI 智能体团队的确定性证据控制内核。**

[English README](README.md)

## 它解决什么问题

在 RAG 和智能体系统中，常见的问题是“引用失效”：来源文档更新、作废或被撤回，但之前基于它写出的结论、报告和记忆仍会被继续使用。更新索引只能让新的回答不再引用旧文档，已经产出的结论并不会自动失效。

YuCe 处理的是后半段：**某条证据被撤回后，哪些已被接受的结论失去了依据。**

- 智能体提交的每条引用，内核都按字节在分配给它的那段原文中核对，对不上就拒绝写入。
- 每条结论都会登记自己依据了哪些引用。证据被撤回时，内核按规则找出以它为依据的结论，其余结论保持不变，**不需要让模型判断撤回影响了哪些结论**。
- 所有被接受的内容都会写入带哈希链的日志；服务在运行中为日志加封印，封印可以签名。任何人都可以不依赖模型，用回执或签名检查点核验公开日志。

内核用 Rust 编写，本身不调用任何模型。任何模型驱动的智能体都可以作为 MCP 客户端接入。

## 0.2 新增

- **什么失去了依据，以及原因。** `sbgk audit-read fallen --wal run.wal` 列出每条失去依据的记录、被撤回的引用（按字节，而不是按文本）及原因、其下仍然有效的引用、其他来源上意思相近的结论，以及应当重新阅读的位置。
- **单条结论的凭证。** `sbgk audit-proof` 为一条记录及其全部依据（直到引用本身）切出一个文件，置于某个封印的签名检查点之下；在对照运行中为 7–24 KB。`sbgk audit-proof-verify` 无需日志、无需模型即可单独核验它。
- **任何人都能核验的日志。** 封印签名为 C2SP 检查点（Ed25519）。`sbgk audit-verify` 用保存在别处的回执或检查点核验日志。核验始终免费。
- **没有任何内容被静默跳过。** `sbgk audit-read coverage` 根据日志、无需模型，说明文档中每个列表项、段落和表格行的结果：已被引用（由哪些记录引用）、因阅读预算未覆盖、被撤回，或未读。补漏阅读（`--gap-pass`，默认关闭）可以把没有引用覆盖的部分作为窄任务重新分给智能体；它按文档 id 的顺序分派，目前没有任何一次运行表明它能提升回答（见 [BENCHMARKS.md](BENCHMARKS.md) 和 [LIMITATIONS.md](LIMITATIONS.md)）。
- **日志旁的索引。** `sbgk audit-index` 生成任何工具都能读取的 SQLite 文件，可随时由日志重建。
- **独立核验器。** `verifier/` 中的 `yuce-verify`：按公开的格式规范独立实现的 TypeScript 程序，与内核不共享代码，也不共享依赖；在 Node.js 和浏览器中检查 J0、J1 两级。

完整变更见 [CHANGELOG.md](CHANGELOG.md)。

## 一分钟演示：撤回一条来源，无需模型，无需 API 密钥

```bash
python examples/revoke-and-replay/demo.py --bin path/to/sbgk --html inspector_report.html
```

三个读者智能体和一个所有者，围绕 MCP 规范中的一页内容走完六个步骤：

1. 改动了一个字节的引用被拒绝，不会写入任何内容。
2. 两条逐字节一致的引用及各自对应的结论被接受，并返回回执。
3. 所有者撤回第一条引用：基于第一条引用的结论失去依据，基于另一条引用的结论保持不变。
4. 停止服务并在同一份日志上重启：重放后根哈希相同，两个状态也相同。
5. 改动了一个字母的日志副本在启动时被拒绝。
6. 无需启动服务，`sbgk audit-verify` 用停止前保存的回执核验日志：原日志通过，被改动的副本被拒绝。

打开 `inspector_report.html`，可离线查看内核在每一步的响应。

## 使用自己的文档

`--docs` 可直接指向一个存放 UTF-8 文本文件的目录（合同、制度、日志、代码等），不需要手写清单：

```bash
sbgk audit-serve --docs ./contracts --run-id contracts-1 --wal contracts.wal \
  --subjects subjects.json --questions questions.json --listen 127.0.0.1:8787
```

隐藏文件（如 `.env`）、服务目录和链接会被跳过；读取和跳过的文件会列在 stderr 中。PDF 和 Word 需要先转换成文本。

**一个智能体，一行配置。** 在 MCP 客户端的配置中加入一项即可，例如 Claude Code 的 `.mcp.json`、Claude Desktop 或 Cursor。客户端会自行启动服务器，不需要另外运行任何程序，也不需要复制令牌：

```json
{"mcpServers": {"yuce": {"command": "yuce", "args": ["mcp", "--docs", "/path/to/my-docs",
                                                     "--ask", "这些文档关于退款说了什么？", "--about", "退款,退货"]}}}
```

- 日志保存在 `my-docs/.yuce/run.wal`，扫描会跳过这个隐藏目录。再次启动时继续同一次运行。
- 智能体得到阅读工具和所有者的只读工具。撤回、封存和关闭默认不开放，可用 `--owner-tools all` 开启。
- 过长的工具结果分段返回，用 `audit_more` 读取其余部分。每段最多 16000 个字符，按字符而不是字节计算，中文一段可达 48 KB。如果客户端保留的工具结果更短，请调低上限，例如 `--max-result-chars 8000`。
- 中文和日文的问题词之间没有空格，请用 `--about` 写明文档中使用的主题词。

**注意：** 日志会保存所读取文档的完整文本，拿到日志的人也就拿到了这些文本。内核与核验均可完全在本地运行，不调用外部模型；但请只把日志交给有权查看这些文档的人。

## 它不做什么

- **只核对字节和结构，不核对含义。** 内核确认引用确实出现在原文中、结论的依据仍然有效，但不判断结论是否准确理解了原文。
- **一条结论在 `based_on` 中列出的引用都是必需的。** 撤回其中任何一条，这条结论就失去依据；只有以另一条独立证据为依据的记录会保留。
- **内核只能看到已登记的依赖；** 未在 `based_on` 中写明的依赖，内核无从发现。
- **仅靠哈希链不能证明历史未被改写。** 要发现被整体重算的日志，或被截短为有效前缀的日志，需要一个保存在日志之外、可信的检查点，例如回执或签名检查点。
- **内核不会自己发现来源被撤回；** 撤回由所有者或外部系统发起。
- **MCP 桥只限制配置了的工具。** 请为每个智能体配置 `--allow-tools`、`--agent-id` 和独立的令牌。服务没有 TLS；监听非本机地址需要 `--allow-remote`。
- **撤回后的重新阅读和核对需要额外的模型调用，** 是智能体的额外工作。
- **规模有限。** 按 0.1 的测量，建议同时最多 8 个智能体、每次运行几千条记录；约 3,000 条记录的真实日志重新打开约需 2 秒。

## 测试结果

同一组智能体分别在接入内核和不接入内核（原生 Temporal、原生 LangGraph）的条件下，阅读 MCP 规范五个版本中的 22 页，并经历两次来源撤回；答案由其他模型盲评。

**我们并不声称提升了回答质量。** 样本量很小，各组差异大多在统计误差范围内。内核增加的是**记录**，不是分数：每条被接受的引用都逐字节一致，每条结论都写明了依据，撤回影响了哪些结论，可以直接从这些链接中读出，而不必询问模型。

- 在 0.2 的对照运行中，同样四家厂商的四个读者，在 0.2 上各阶段正确率都是 98.9%，在 0.1.7 上为 86.5–88.8%；但每一侧只有一次运行。
- 在第二个语料（A2A 规范）上，开启补漏阅读的一侧按预注册规则表现更差：把已结束的事实说成仍然有效的次数更多。日志显示，内核为“哪些结论已过时”这一问题挑选记录的规则漏掉了更新日志中以 “removed”“renamed” 表述的变更；这一比较无法区分该缺陷与补漏阅读各自对差异的影响。0.2.1 已修正这条规则，但尚未用模型重新测量。

**代价：** 在 Haiku 上耗时是 2.3 到 2.5 倍，成本是 1.4 倍；在 DeepSeek 上耗时是 1.2 到 1.3 倍，成本是 1.5 到 1.6 倍。完整数据见 [BENCHMARKS.md](BENCHMARKS.md) 和 [LIMITATIONS.md](LIMITATIONS.md)。

## 名字：玉策 → 玉冊

项目最初名为 R2R，即 *Recipe to Receipt*（从“指令”到“回执”）。**YuCe** 取两个同音词 *yù cè*：

- **玉策**（指令）：内核每次交给智能体的一个有界任务，例如“阅读这份文档的这一段”。
- **玉冊**（回执）：被接受的提交按哈希链装订成册；每次提交都有回执，运行完成时会有一份写明状态根的最终回执。

将“玉策”读作“指令”、“玉冊”读作“回执”，是本项目自己的解释。
